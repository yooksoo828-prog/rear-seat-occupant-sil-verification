# AI 활용 방안 — 보조 도구로 쓴 방법과 사람이 한 일

> **초안** — 2026-11-25. AI(Claude)가 팀장의 요구로 작성함. 팀 확인 전.
> 이 문서는 AI를 **무엇에, 어떤 방식으로, 어떤 통제 아래** 썼는지와, 그동안 **사람이 무엇을 결정하고 확인했는지**를 저장소 기록(커밋, Pull Request, 문서)에 근거해 정리한 것이다. **기록으로 확인되지 않는 것은 적지 않았고**, 팀만 아는 사실은 8절의 빈 칸으로 남겼다.

## 1. 핵심 메시지
1. **결정은 사람이 했다.** 시험 입력, 판정 기준, 시험 범위, 반복 횟수, 한계의 수용 여부는 팀장이 날짜와 함께 결정했고 그 결정이 기준선 파일에 기록되어 있다(3절).
2. **AI가 쓴 코드는 사람의 결정에 맞는지 기계적으로 검증된다.** 사람이 정한 기준선의 상수 87개를 코드 값과 대조하고, 하나라도 다르면 시험이 시작되지 않는다. AI가 만든 코드가 사람의 결정을 벗어날 수 없게 한 구조이다.
3. **AI의 결과는 사람이 읽고 확인했다.** 팀장이 최종 보고서를 직접 수정했고, 문서의 모순을 짚어 AI가 정정했으며, 팀원 2명이 Pull Request에서 승인했다(4절).
4. **AI는 승인을 대신하지 않는다.** 하지 않은 합의·승인 기록을 만들지 않았다(6절).
5. **AI에 의존한 부분도 숨기지 않는다.** 코드와 문서 초안은 AI가 작성했다고 선언문에 공개했다(2절, 선언문 2절).

## 4. 사람이 AI의 결과를 확인하고 교정한 사례
| 사례 | 무슨 일이 있었나 | 근거 |
| --- | --- | --- |

## 6. AI가 하지 않는 것
1. 사실이 아닌 기록(합의, 승인, 전달, 실행 시각)을 만들지 않는다. 확인되지 않은 것은 "미실시"로 남긴다.
2. 승인과 합의를 대신하지 않는다. AI 검토는 "충족" 판정이 아니다.
3. 모르는 사실을 채우지 않는다(예: 사건 작성자는 팀장이 확인한 뒤 기록).
4. 결과를 본 뒤 합격 기준을 바꾸지 않는다(D6, 불합격 3건 그대로 기록).
5. 개인정보와 저작권을 지킨다. 팀원 실명 마스킹, 대화 캡처 미업로드, 논문 그림 16개와 PDF 미업로드.

| --- | --- | --- |
| 증거 위치를 놓침 | AI가 저장소만 보고 "증거 없음"이라고 답함 | Notion 확인 후 정정 |
| 검증 스크립트 오류 | TM-05 대조에서 "TC-01~05" 범위 표기를 펼치지 못해 불일치로 잘못 판정 | 원인 확인 후 정정 |
| 낡은 문구 방치 | 공통 정보 표의 승인 기록을 갱신하지 않음 | 하단 추가 기록으로 명시 |
| 승인 시각 | PR #9의 두 번째 승인이 병합 17초 뒤에 제출됨 | 숨기지 않고 체크리스트에 기록 |

| 독립성 | 문서를 쓴 AI가 검토도 함 | 팀원 승인으로 보완하되 한계로 공개 |

**AI의 한계**: 요약과 설명은 내용의 정확성을 보증하지 않는다. 시험 결과는 SIL 모델과 가상 반사면 입력에 대한 것이며 실제 센서 성능을 입증하지 않는다. **코드와 문서 초안 작성은 AI에 크게 의존했다.**

## 9. 예상 질문과 답 (기록 근거 포함)
> **주의**: 아래 "답"은 AI가 저장소 기록에 맞춰 쓴 **초안**이다. 말씀하실 때는 **본인이 실제로 한 것만** 말하고, 기억과 다르면 고쳐서 말할 것. 기록에 없는 것을 더하지 말 것.
**Q. AI는 어떻게 썼나요?**
A. Claude를 보조 도구로 썼습니다. 시험 코드와 문서 초안을 쓰게 하고, 결과를 대조·검증하게 했습니다. 시험의 기준과 범위, 결과 해석은 제가 정했고, 그 결정은 기준선 파일에 날짜와 함께 남아 있습니다.

**Q. 직접 한 것은 무엇인가요?**
A. 시험 입력과 판정 기준(D1~D8)을 정했습니다. 실제 더미 치수 근거가 없어서 가상 반사면으로 바꾸고 원 조건 결과로 세지 않기로 했고, 목표 1%를 통계로 확인하려고 반복을 60에서 300회로 올렸으며, 합격 기준은 결과를 보기 전에 고정했습니다. 결과가 나온 뒤에는 같은 높이 화물 구분 불가를 알고리즘을 고치지 않고 한계로 받아들였고, 50 °C 문제는 온도 보정을 채택해 v1.1로 확인했습니다. 마감 때문에 범위를 줄인 결정도 제가 했고 사유를 문서에 남겼습니다.

**Q. AI가 쓴 코드를 어떻게 믿나요?**
A. 제가 정한 기준선 상수 87개를 코드 값과 대조해서 하나라도 다르면 시험이 실행되지 않게 했습니다. 시험을 두 번 돌려 같은 결과인지, 다른 컴퓨터에서도 같은지 확인했고, GitHub이 변경마다 자동으로 다시 검사합니다.

**Q. AI가 틀린 적은 없나요?**
A. 있었습니다. 처음에 증거가 없다고 잘못 판단했고, 검증 스크립트가 범위 표기를 잘못 읽은 적도 있습니다. 그런 정정은 `docs/ai_usage.md` 7절에 기록해 두었습니다.

**Q. AI가 안 했다면 이 결과가 나왔을까요?**
A. (솔직하게 직접 답변. 코드 작성은 AI에 크게 의존했고, 기준 설정과 결과 판단은 팀이 했다는 구분으로 설명 가능.)
