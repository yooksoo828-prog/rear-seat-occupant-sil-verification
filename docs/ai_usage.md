## 4. AI가 하지 않는 것 (원칙)
1. **사실이 아닌 기록을 만들지 않는다.** 하지 않은 합의, 승인, 전달, 실행 시각을 적지 않는다. 확인되지 않은 것은 "미실시", "확인되지 않음"으로 남긴다.
2. **승인과 합의를 대신하지 않는다.** AI 검토는 "충족" 판정이 아니다. 승인은 팀원이 직접 한다.
3. **모르는 사실을 채우지 않는다.** 예: 사건 작성자는 팀장이 직접 확인한 뒤에 기록했다. 교훈은 회의를 하지 않았다는 사실과 AI가 기록에서 도출했다는 출처를 문서에 밝혔다.
4. **결과를 본 뒤 기준을 바꾸지 않는다.** 합격선과 목표는 불합격 3건을 포함해 그대로 기록했다(D6).
5. **개인정보와 저작권을 지킨다.** 공개 저장소에 올리기 전에 팀원 실명을 마스킹했고, 대화 캡처는 올리지 않았다. 논문에서 가져온 그림 16개와 논문 PDF는 올리지 않았다.

## 5. 활용 절차
```
사람이 요청·결정
   ↓
AI가 초안·구현 (사실은 저장소 기록과 결과 파일에서 확인)
   ↓
AI가 자체 검증 (스크립트 실행, 수치 대조, 재현 실행)
   ↓
커밋 (AI 참여는 Co-Authored-By로 표기)
   ↓
Pull Request  →  팀원 승인 (기록이 남음)
   ↓
병합 후 체크리스트에 승인 근거 기록
```
**사람이 반드시 거치는 지점**: 기준선 확정, 범위 변경 결정, Pull Request 병합, 팀원 승인, 제출물의 최종 내용.

## 6. 한계와 실제로 있었던 정정
AI가 틀리거나 못 한 것을 숨기지 않고 기록한다.

| 사례 | 내용 | 처리 |
| --- | --- | --- |
| 증거 위치를 놓침 | AI가 처음에 저장소만 보고 "표준 준수 증거가 없다"고 답함. 증거는 Notion에 있었음 | Notion을 확인한 뒤 정정하고 문서를 저장소로 이전 |
| 검증 스크립트 오류 | TM-05 대조에서 "TC-01~05"의 범위 표기를 펼치지 못해 불일치로 잘못 판정함 | 원인을 확인해 오류가 아님을 정정 |
| 승인 시각 | PR #9의 두 번째 승인이 병합 17초 뒤에 제출된 사실이 있었음 | 숨기지 않고 체크리스트에 사실대로 기록 |
| 레이아웃 미확인 | 이 환경에는 Word·PowerPoint 렌더링 도구가 없어 최종 보고서·발표자료의 화면 배치를 확인하지 못함 | 사람이 직접 열어 확인하도록 안내 |
| 접근 불가 | Notion의 일부 원본 페이지가 열리지 않아(404) 내보내기 파일로 대체함 | 내보내기 범위의 한계를 문서에 명시 |
| 독립성 | 문서를 쓴 AI가 검토도 함 | 팀원 승인으로 보완하되 한계로 공개함(선언문 2절) |

그 밖의 한계: AI의 요약과 설명은 **내용의 정확성을 보증하지 않는다.** 시험 결과는 SIL 모델과 가상 반사면 입력에 대한 결과이며 실제 센서 성능을 입증하지 않는다.

## 7. 앞으로의 사용 방침
| 해도 되는 것 | 사람이 확인해야 하는 것 | 하지 않는 것 |

| 초안 작성, 코드 구현 | 수치와 결론의 최종 확인 | 사실이 아닌 합의·승인 기록 작성 |
| 결과 파일과의 대조, 재현 실행 | 범위 변경, 완료·종료 결정 | 승인 대행 |

| 위험·불일치 지적 | 팀원 승인 요청과 병합 | 결과를 본 뒤 합격 기준 변경 |
