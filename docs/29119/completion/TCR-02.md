## 7.4.2 수행한 시험 요약

- **대상**: HC-SR04 특성을 참고한 센서 모델과 점유 판정기(Python SIL). 실제 하드웨어·차량 시험이 아니다. 입력은 가상 반사면(H_s 100 cm, 빈 좌석 0, R0~R3 = 5/20/40/60 cm)이며 더미·인체·가방 치수가 아니다(D1). 잡음·손실·움직임·온도 입력 오차는 프로젝트 가정이다.
- **v1.0**(2026-11-11): 기준선 v1.0(SHA-256 `79f21ce9…`, 87개 상수 일치)으로 TC-01~TC-16을 실행해 결과 행 152개를 얻음. 목표 충족(통계 확인) 49, 일치 27, 기준 충족(전 시행) 12, 기록 44, 가정 기반 민감도 기록 13, 미실행 4, 불합격 3.
- **v1.1**(2026-11-21): 온도 보정을 기본값으로 켠 기준선 v1.1(SHA-256 `9c1f4635…`)로 TC-01~TC-16을 같은 입력·시드·반복 수로 재실행함(27초). **판정이 달라진 행 0 / 152, 시행 결과가 달라진 시행 0 / 9,855**, 환산 오차 평균 1.100 cm → 0.741 cm(`V1.0-vs-V1.1.md`).
- 이번 시험에서 불합격으로 기록한 것은 3건이며(IR-01~03) 합격선을 바꾸지 않았다.

## 7.4.3 계획 대비 변경

1. **계획이 실행보다 늦었다.** v1.0 본시험(2026-11-11)이 계획서 TP-01(2026-11-12)보다 먼저 실행되었다. 29119 형식의 계획·설계·환경·결과 문서는 실행 후에 작성했다(TS-01, TPS-01에 사후 기록임을 명시).
2. **원 조건 4행 미실행.** O-A, O-B, O-C 원 조건과 TC-12(O-S)는 대상 치수가 없어 실행하지 못했다. 가상 반사면 R1·R2·R3 대체 조건으로 실행했고 원 조건의 결과로 세지 않았다. v1.1에서도 실행하지 않았다.
3. **반복 횟수.** TC-01, TC-04는 시험 설계의 계획값 60회가 아니라 300회로 올려 실행했다(D5).
4. **v1.1은 최소 범위.** 계획(추가 시험 케이스 4개 TC-07e·14b·15b·15c, 원 조건 대상 치수, H_s 110 cm 조건)보다 좁게, 온도 보정 기본값 변경 한 가지만 실행했다(팀장 결정 2026-11-21, TS-02).
5. **일정 지연.** v1.1 실행은 계획(11/18)보다 3일 늦은 11/21에 수행했다.
6. **환경 버전 차이.** 팀장 PC의 Python 3.13.2, numpy 2.5.5가 v1.0 기록(3.13.18, 2.5.3)과 달랐다. 결과 동일을 확인하고 팀장이 허용하기로 결정했다(TER-01 추가 기록).
7. **문서 밖 추가 시험.** TC-14에서 연속 4회 치환 경계 확인을 계획 밖으로 추가 실행했다(TCS-01에 표시).

**평가 결론**: 완료 기준의 일부(경계값·상태 전이 커버리지 100%)를 **달성하지 못했다.** TP-01 7.2.7.7이 "최선을 다해도 100%가 안 되면 사유를 한계로 기록한다"고 정했으므로 사유를 적는다: 추가 시험 케이스(TC-07e, 14b, 15b, 15c)를 마감 일정 때문에 구현하지 않았다. 그 결과 다음이 **시험되지 않은 채 남아 있다**: 최초 판정 중간값 주변(Δ 6.5, 8.5 cm), 유효 거리 경계(2, 3, 399, 400 cm), 갱신 중단 시간 경계(0.9, 1.0, 1.1 s), 비점유 상태에서의 갱신 중단 전이(S8). 이 항목들은 시험을 통과했다는 의미가 아니라 시험하지 않았다는 의미이다.

이 시험은 합격선·목표·시행 수를 결과를 본 뒤 바꾸지 않았고(D6) 불합격 3건을 그대로 기록했다.

## 7.4.7 잔여 위험

- **시험하지 않은 경계값·전이**(7.4.4 평가 결론). 
- **IR-01·02**: 거리 하나만 쓰는 판정기는 같은 거리 이력의 정지 화물과 점유 대상을 구분하지 못한다(구조적 한계, 버그 아님). 한계로 수용했다.
- **IR-03**: v1.1에서 보정을 기본으로 켜도 판정이 같음을 확인했으나, 종결은 팀 합의가 필요하다. SR-09 전체 충족은 대상(빈 좌석·R2·R0)과 온도(0·20·50 °C)가 제한적이라 선언하지 않는다(D3).
- **원 조건 대상 미실행 4행**: 실제 더미·인체·가방에 대한 결론이 없다.
- **follow_up_items**: 초기 빈 좌석 실측 보정(d_empty), 차량 시동과 센서 전원의 관계, 착석 위치 분포는 모델에 없다.
- **재현 환경**: 문*호 환경에서의 재현은 미확인이다.
- **독립성**: 문서 작성과 검토를 같은 AI가 수행했다(선언문 2절에 공개). 팀원 승인으로 보완하지만 독립 검토는 아니다.

## 7.4.10 교훈

**출처와 한계(중요)**: 교훈 회의는 **하지 않았다.** 팀원들이 별도 의견이 없다고 해서(팀장 전달, 2026-11-21) 팀장이 작성을 위임했고, 아래는 **AI(Claude)가 이 저장소의 기록(TCR-01, TS-01·02, TRR-01, TEL-01, TER-01, PR 기록)에서 사실로 확인되는 것만 도출**한 것이다. 팀원이 직접 정한 교훈이 아니며, 팀원 확인은 PR #9 승인으로 받았다(2026-11-21). 승인된 커밋은 작성 당시 커밋과 같아 승인 과정에서 수정은 없었다. 다만 승인은 문서 전체에 대한 것이며 교훈을 팀원이 직접 정했다는 뜻은 아니다.

**잘 된 것**
1. **기준선을 해시로 고정하고 변경은 버전을 올린 것.** v1.0 파일을 건드리지 않았기에 v1.1과 행 단위로 비교해 "판정 변화 0"을 입증할 수 있었다.
2. **수기 집계를 자동 검증으로 바꾼 것.** 체크리스트를 CSV와 CI 검증으로 옮기자 outcome 개수(원문 41개), 상태 값, '충족'의 검토자·승인 기록 누락을 기계가 막고(증거 없이 충족으로 바꾸면 검증이 실패함을 시험으로 확인), 집계는 CSV에서 자동 계산되었다.
3. **합의·전달을 PR 승인으로 남긴 것.** 카카오톡 "OK"에는 원본이 없어 증거가 약했지만(7.2.3 b·h의 지적), PR #5·#7은 승인자·시각·승인한 커밋이 남았다.

**아쉬웠던 것과 다음에 바꿀 것**
4. **계획이 실행보다 뒤였다.** 완료 기준과 일정, 합의를 실행 전에 정했어야 한다(TP-01이 실행 하루 뒤 작성). 다음에는 기준선 확정 전에 계획서와 완료 기준 합의를 끝낸다.
5. **문서에 없는 실행 의존은 다시 돌려 봐야 드러났다.** `sil_prelim/` 폴더 의존은 재실행에서 `FileNotFoundError`로 처음 발견되었다. 새 환경에서의 재실행을 계획 단계에 포함한다.
6. **실행 시각을 기록하지 않았다.** v1.0 시각은 파일 수정 시각에 의존했다(TEL-01 한계). v1.1부터는 실행 시각과 환경을 기록했다. 처음부터 실행 명령 앞뒤에 시각을 남기는 습관이 필요하다.
7. **환경 버전 기준이 없었다.** 환경 버전이 기록과 다를 때의 정책이 없어 사후에 허용 결정을 해야 했다. 허용 버전 범위와 동일 확인 방법을 계획서에 미리 적는다.
8. **범위를 마감에 맞춰 일찍 정하지 못했다.** 추가 케이스와 대상 치수를 계획했으나 구현하지 못해 완료 기준 일부를 달성하지 못했다. 처음부터 필수와 선택으로 나눠 필수를 먼저 끝낸다.
9. **작성과 검토를 같은 AI가 했다.** 독립성이 약하므로 팀원 검토를 문서 초안 단계부터 받는다.
